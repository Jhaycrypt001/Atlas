An agent that settles real money, non-custodially.

Atlas turns a plain-English instruction — “pay this freelancer 5 USDC once the work is verified” — into a real on-chain settlement. The user funds and signs from their own wallet; the agent orchestrates escrow and release but never holds the money.

Get running

Quickstart

Two minutes from clone to a live settlement on testnet.

# install & compile contracts
npm install
node scripts/compile.mjs        # contracts/ -> artifacts/

# start the ASP server + live console
npm run asp                     # -> http://localhost:4173

Open /app, click Connect wallet, and type an instruction:

Pay 0x7099…79C8 5 USDC for the logo
You need testnet OKB (gas) and TestUSDC in the connected wallet — funds come from you, not the agent. A pay-and-verify flow is ~3 transactions, so keep a small gas buffer.
How it settles

Non-custodial by construction

Every value-moving capability routes through one escrow contract. The agent’s key deploys the escrow and triggers release, but the contract — not the agent — holds funds and enforces who gets paid. A compromised agent key cannot redirect escrowed money: it can only release to the fixed payee or refund the original funder.

GuaranteeEnforced by
Funds come from the user, not the agentEscrow.funder = connected wallet; lock() pulls from funder
Only the agent can releaserelease() gated: require(msg.sender == agent)
Refund returns to the funderrefund() transfers to funder, not agent
Fee is skimmed on settlementrelease() pays payee amount−fee, treasury fee (0.5%)
What it does

Four capabilities

Each is a plugin over the same kernel — it inherits settlement, the spend gate, the ledger, and the ASP surface for free.

pay

Pay

Send a payment held in escrow until conditions are met, released on completion.

getPaid

Get paid

Issue an invoice and collect the client’s funds into escrow.

split

Split

Divide an amount across several recipients — one escrow per payee, each funded by you.

verify

Verify

Release only after a proof passes: LLM receipt check, signed webhook, or on-chain attestation.

Operate safely

Security posture

Atlas moves real money, so the defaults fail closed. Controls, by what they protect:

ControlBehaviorState
User-funded settlementEscrow funded & signed by the user; agent never custodiesenforced
Agent-funded path/intent is unauthenticated — off unless DEMO_MODE=1closed
Proof-gated releaseverify rejects self-referential proof; needs real evidenceenforced
Spend capValue tasks over MAX_VALUE_USDC are blockedenforced
Rate limitingPer-IP throttle on gas/fund routesenforced
TLS fail-closedRefuses to start with TLS verification offtestnet override
Error leakageGeneric client errors; detail logged server-sidecontained
Before a public deploy: keep DEMO_MODE=0, serve over HTTPS (unset ALLOW_INSECURE_TLS), rotate PK if it has ever been shared, and put a gateway rate limiter in front for multi-instance.
