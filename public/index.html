How it works

Integrates easily

From plain-English intent to settled transaction in three steps. No custody, no trust assumptions, and nothing to integrate beyond one HTTP endpoint.

01

Submit an intent

Type it, or POST it to /asp/run. "Pay 0x7099… 200 USDC for the logo." The planner routes it to the right capability.

02

Escrow locks, proofs verify

A per-agreement escrow contract deploys and locks the funds. Receipts, webhooks, or on-chain attestations decide the release.

03

Settle & audit

Funds release to the payee and the fee accrues to treasury. Every step is a transaction you can open in the explorer.

Capabilities

Built for agentic finance

Four value-moving capabilities behind one manifest: discoverable, signed, and billable per call. Each one runs through the same safety gate and settles through the same escrow kernel, so adding a new capability never touches the core.

escrow · non-custodial

→ Pay

Lock funds in a fresh escrow per agreement, release on completion. The agent never holds your money; the contract does.

invoice · x402

← Get Paid

Issue invoices and accept x402 pay-per-call. A 402 challenge prices the request; a signed payment settles it.

n-way

⑃ Split

One intent fans out to many payees. Team payouts, rev-share, refunds, all settled concurrently with serialized nonces.

proof adapters

✓ Verify

Release against evidence: LLM receipt checks, HMAC webhooks, or on-chain attestations. Pluggable proof registry.

FAQ

Frequently asked questions

Everything you need to know before your first intent.

What exactly does Atlas do?

Atlas is a single agent service that executes on-chain financial operations from plain-English intents: paying with escrow, invoicing, splitting funds, and verifying deliverables before release. All of it runs concurrently on X Layer.

Does Atlas hold my funds?

No. Every payment locks into a fresh non-custodial escrow contract deployed per agreement. Release conditions are enforced by the contract and proof adapters, not by the agent.

How do other agents discover and call Atlas?

Atlas serves an asp/1.0 identity manifest at /.well-known/asp.yaml with feed and inbox endpoints. Calls are authenticated with Ed25519 ASP-Sig, and /asp/run can be billed per call via the x402 protocol.

What counts as proof of delivery?

Three adapter types today: LLM-judged receipts, HMAC-signed webhooks, and on-chain attestations. The registry is pluggable, so new proof types drop in without touching the kernel.

Which network does it run on?

X Layer (OKX's chain). Testnet today, chain id 1952, with the same code path for mainnet. Every transaction links out to the OKX explorer.
